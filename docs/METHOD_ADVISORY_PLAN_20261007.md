## 2. 메일 구조 (서면 자문 의뢰)

제목 예: `[자문 의뢰] 영농형 태양광 후보 공간의 공간 단위·클러스터 정의 방법론 서면 자문 요청 — PLANiT`

1. **의뢰 배경** (3–4문장) — 전국 필지 전수 분석으로 영농형태양광 특별법 시행 후 농업진흥지역 개방의 근거를 제시하는 연구. 결과는 공개 사이트와 논문으로 발행 예정.
2. **자문 범위** — 이번 자문은 **공간 분석 단위와 최종 클러스터(사업 단위) 정의, 우선순위 비교 방법**의 타당성. 자료의 정확성·현실성(경기도 데이터 자문)은 별도로 진행 중이며 이번 범위 아님. 법적 인허가·계통 접속·경제성 판단은 범위 밖.
3. **현재 상태 5줄** — ① 필지 판정 → 21m 이내 연접 → 후보 공간(`analysis_unit_v1`, 면적 하한 없음) ② 21m는 k-거리 곡선 무릎에서 유도(간격 실체 = 구거·도로) ③ 그 다음 단계였던 ≤1,000m 응축은 근거 없는 문턱이라 2026-09-23 활성 계보에서 폐기 ④ 대안 3계열(밀도·그래프 커뮤니티·씨앗 집적) 비교 결과 교체 근거를 찾지 못함 ⑤ 최종 클러스터 정의는 **의도적으로 비워 둠(BLANK)** — 이번 자문으로 채우려 함. 우선순위는 3축 비지배 집합(가중치 없음).
4. **질문** — §3의 M1–M8 (브리프와 동일 번호).
5. **볼 곳** (링크 3–4개) — 방법론 자문 브리프(`docs/METHOD_ADVISORY.md` Pages 또는 PDF) · `method.html#…`(3-3 연접 기준 · 4 우선순위 비교) · 자문 화면(`cluster_advisory.html` — 브리프 화면판 · 전국 21m 단위 지도 · M1–M10 입력) · 방법 비교 사례집 축약판.

## 3. 자문 질문 초안 (M1–M8)

- **M1 최소 공간 분석 단위** — 적격 필지를 21m 이내 연접으로 묶은 단위(단일연결 절단 = 연결성분)를 최소 분석 단위로 쓰는 것이 타당한가. 도로·구거를 건너 묶는 설계가 사업 부지 개념과 맞는가.
- **M2 21m 유도 방법** — k-거리 곡선(k=4) 무릎에서 임계를 정한 방법의 적절성. 대안(법정 기준·지적 인접·도로 경계 기반)이 있는가. 15·21·25m 민감도 제시 방식은 충분한가.
- **M3 최종 클러스터 정의의 필요성과 원리** — 21m 단위 위에 "사업 단위" 층이 필요한가. 필요하다면 거리 임계·밀도·커뮤니티·목표 규모 집적 중 어떤 원리가 맞고, **임의 문턱(1,000m·목표 면적) 없이** 정당화하는 방법은 무엇인가.
- **M4 ≤1,000m 응축 폐기 판단** — "근거 없는 문턱이 하류 전체에 임의성을 전파한다"는 이유로 폐기한 판단의 적절성. 복원한다면 어떤 근거가 필요한가.
- **M5 방법 비교 설계** — PR-0042의 5축 11지표(규모·파편화·체인·행정 걸침·안정성)와 비지배 판정으로 방법을 비교한 설계의 적절성. 빠진 지표(응집도 compactness · 도로 관통 · 소유 혼합 등)가 있는가.
- **M6 우선순위 비교** — 시군 안 3축(면적·계통 여유·산단 거리) 비지배 집합을 제시하고 가중합·종합점수를 쓰지 않는 방침의 타당성. 가중합을 쓴다면 정규화·가중치 도출(AHP 등) 방법과 축 추가 의견. 결측 = 축 최악값, 동률 ≠ 지배 규칙의 적절성.
- **M7 MAUP·민감도 서술** — 규모·구획 효과를 보고서·논문에서 어떻게 서술하고 어떤 민감도 표를 병기해야 하는가.
- **M8 용어** — "후보 공간"(21m 단위) · "클러스터"(미정) · "특구"를 구분해 쓰는 현재 표기의 적절성과 권장 표현.

(자문자 전공이 환경영향평가 분야라면 M9로 "환경 제약 레이어를 단위 정의 단계에 넣을지, 판정 단계에 둘지"를 추가.)

## 5. 작업 순서와 승인 지점

1. a → b → c → d 순으로 로컬 작성 (main에서 직접 · 공유 작업트리이므로 명시 경로만 `git add`).
2. 로컬 정적 서버로 `cluster_advisory.html`·`method.html`·브리프 렌더 확인, site_gate 실행.
3. 사용자 육안 검수 → **push는 사용자 Run 버튼**(공개 행위).
4. 메일 본문 최종본 작성(§2 구조) → 사용자가 발송.
